# SHUZU

**VPN-клиент с ядром внутри.** Windows и Android, тёмный интерфейс, авто-выбор сервера,
диагностика сети и проверка блокировок провайдера.

## Что это

SHUZU — клиент для своих подписок (VLESS/Reality, VMess, Trojan, Shadowsocks, Hysteria2, TUIC).
Ядро **sing-box** и tun2socks **hev-socks5-tunnel** лежат внутри установщика и APK: ничего
докачивать вручную не нужно, никаких «положите core.exe рядом». Скачал → установил → вставил
подписку → подключился.

| Windows | Android |
|---|---|
| `SHUZU-Setup-1.0.0-x64.exe` | `SHUZU-1.0.0-android.apk` |
| TUN на весь компьютер + режим системного прокси | VpnService, плашка в шторке с сервером, пингом и кнопкой «Отключить» |

## Возможности

**Подключение**

- Большая кнопка, авто-выбор лучшего сервера по пингу, джиттеру и потерям.
- Список серверов с флагами, городами, пингом в реальном времени и избранным.
- Несколько подписок одновременно, у каждой — свой срок и остаток трафика.
- Автообновление подписок по расписанию, ручное обновление одной кнопкой.
- Быстрое подключение к избранному серверу одним касанием.

**Сеть**

- Режим **TUN** (весь трафик, включая приложения, которые игнорируют системный прокси).
- Режим **системного прокси** — работает без прав администратора.
- **Белые списки**: банки, госуслуги, маркетплейсы, операторы и другие российские сервисы
  идут напрямую, остальное — через туннель. Список правится в настройках.
- Блокировка рекламы и трекеров на уровне DNS/маршрутов.
- DNS через туннель (DoH) или системный — по выбору; защита от подмены DNS.
- Исключение локальной сети, чтобы не ломать принтеры, NAS и роутер.

**Диагностика**

- **Проверка соединения** — 15+ проверок с весами: ядро, Wintun, права, DNS, маршруты,
  MTU, hosts, системный прокси, брандмауэр, другие VPN-адаптеры, антивирус, время, порт сервера.
  Каждая проблема — с человеческим объяснением и кнопкой исправления.
- **Проверка блокировок** — сравнение доступности российских сервисов и глобальных
  (Google, YouTube, Cloudflare, Telegram, MIUI). Если работают только ВК/Госуслуги/Яндекс —
  провайдер фильтрует трафик; если открыто всё — фильтрации нет.
- Логи ядра и приложения прямо в интерфейсе.

**Обновления**

- Проверка новых версий через GitHub Releases, баннер в профиле, скачивание и установка
  внутри приложения (`/S`-установка на Windows, `ACTION_VIEW` для APK на Android).

## Установка

### Windows 10/11 x64

1. Скачайте `SHUZU-Setup-*.exe` из [Releases](https://github.com/kayorissss/SHUZU/releases).
2. Запустите установщик. SmartScreen может предупредить: «Неизвестный издатель» — подпись
   кода не настроена, это нормально для открытой сборки. «Подробнее» → «Выполнить в любом случае».
3. Запустите SHUZU. Для TUN-режима приложение попросит права администратора
   (создание виртуального адаптера Wintun). Без прав доступен режим системного прокси.

### Android 10+

1. Скачайте `SHUZU-*-android.apk` из Releases.
2. Откройте файл и разрешите установку из этого источника (система спросит сама).
3. Запустите, разрешите VPN и уведомления — без них не будет работать туннель и плашка статуса.

> Публичный APK подписывается постоянным release-ключом. Устанавливайте обновления
> поверх старой версии, не удаляя приложение. Настройка подписи: [docs/SIGNING.md](docs/SIGNING.md).

## Первый запуск

Два способа добавить серверы — ровно как в макете:

- **«+ Из буфера обмена»** — скопируйте ссылку-подписку или отдельные `vless://`-ссылки и нажмите кнопку.
- **«QR-код»** — камера, наведите на QR из панели провайдера.

Под кнопкой «⋮» — вставить вручную, загрузить файл (`.txt`, `.yaml`, `.json`, base64), вставить
из файла конфигурации sing-box. Поддерживаются форматы: base64-список ссылок, Clash YAML,
sing-box JSON, одиночные ссылки.

Дальше: подождите пару секунд (идёт замер пингов) → нажмите круглую кнопку.

## Если не работает

Откройте **Ещё → Диагностика → Проверить**. Приложение само скажет, в чём дело. Типичные причины
для ноутбука, на котором «не работает ни один VPN, а на телефоне работает»:

| Симптом | Что проверяет SHUZU | Что делать |
|---|---|---|
| Туннель поднимается, интернета нет | Wintun, MTU, маршруты | Переустановить Wintun (диагностика предложит), уменьшить MTU до 1380 |
| Подключение обрывается через минуту | Другой VPN-адаптер, брандмауэр | Удалить остатки OpenVPN/TAP, отключить фильтрацию в антивирусе |
| Сайты не открываются, пинг сервера есть | DNS, hosts, прокси | Сбросить прокси, включить DNS через туннель |
| Не подключается ни один сервер | Время, порт сервера | Синхронизировать часы; сменить порт/сеть |
| Работает только с телефона в режиме модема | Раздача через CGNAT/NAT телефона | Проверить, что телефон не блокирует UDP; попробовать TCP-режим |

Проверка блокировок покажет, фильтрует ли провайдер трафик: сравнение локальных и глобальных
сервисов отделяет «провайдер режет» от «сервер не работает».

## Сборка

```bash
npm ci

# интерфейс + Electron (Windows .exe)
npm run build
npm run dist:win        # нужны скачанные ядра -> npm run cores

# Android (нужны JDK 17 и Android SDK)
npm run cores           # sing-box для Android -> jniLibs, tun2socks -> app/libs
npm run android:sync    # сборка web-части и копирование в android/
cd android && ./gradlew assembleRelease
```

Ядра не хранятся в репозитории: `scripts/fetch-cores.sh` скачивает sing-box нужной версии
(переменная `SINGBOX_VERSION`) и hev-socks5-tunnel, раскладывая бинарники по местам. Именно это
делают GitHub Actions при сборке релиза — см. [.github/workflows/release.yml](.github/workflows/release.yml).

Проверки перед релизом:

```bash
npm run verify   # tsc + тесты логики + синтаксис Java + смоук интерфейса + генерация конфигов
```

CI дополнительно прогоняет сгенерированные конфиги через настоящий `sing-box check`.

## Как устроено

```
renderer (React + framer-motion)      — интерфейс, один код на ПК и телефон
        │ window.shuzu (ShuzuApi)
        ├── Electron main                ├── Capacitor + Java (Android)
        │   ├─ sing-box.exe + wintun     │   ├─ VpnService -> hev-socks5-tunnel
        │   ├─ Clash API (пинг, трафик)  │   ├─ sing-box (nativeLibraryDir)
        │   └─ диагностика Windows       │   └─ foreground-служба + плашка
        └──────── общий TypeScript: разбор подписок, генерация конфига, оценка серверов
```

- Конфиг ядра генерируется из подписок: outbound на сервер, `urltest` для авто-выбора,
  `selector` для ручного, правила для белых списков, рекламы и DNS.
- Пинг — TCP-хендшейк параллельно (8 потоков), затем уточняется через туннель.
- Android: TUN → tun2socks → локальный SOCKS5 ядра; трафик самого приложения исключён
  через `addDisallowedApplication`, поэтому нет петли.
- Экономия батареи: никаких таймеров чаще 2 с, замеры пинга пачками, `IMPORTANCE_LOW`
  у плашки, отсутствие постоянных wake-lock'ов.

Подробнее — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Сборка и релизы — [docs/BUILD.md](docs/BUILD.md).
Частые вопросы — [docs/FAQ.md](docs/FAQ.md).

## Приватность

- Никакой телеметрии и аккаунтов. Настройки, подписки и серверы хранятся локально.
- Сеть используется только для: загрузки ваших подписок, замера пинга, проверки обновлений
  на GitHub и запросов диагностики (список доменов виден в коде, `shared/rules.ts`).
- Пароли и ключи из подписок попадают только в конфиг ядра, который пишется в приватный
  каталог приложения.
